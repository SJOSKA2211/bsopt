## 2025-02-18 - JWT Algorithm Confusion Prevention
**Vulnerability:** The application was vulnerable to JWT Algorithm Confusion (CVE-2015-9256) because `TokenService.decode_token` relied on the unverified `alg` header extracted via `jwt.get_unverified_header()` to dynamically determine which key to use for validation. This could allow an attacker to forge tokens by submitting an asymmetric token signed symmetrically (HS256) using the application's public key.
**Learning:** Security configurations for validation should be strict and static where possible. Trusting input metadata (like the unverified JWT header) to dictate the validation algorithm violates the principle of "trust nothing, verify everything" and can lead to severe cryptographic bypasses.
**Prevention:** Always enforce the configured algorithm (e.g., `settings.JWT_ALGORITHM`) during token verification (`jwt.decode`) and never dynamically extract or trust the `alg` header via `jwt.get_unverified_header()`.
