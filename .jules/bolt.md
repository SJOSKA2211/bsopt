## 2024-04-21 - Offloading N+1 data iteration to database
**Learning:** MathKernelService was previously fetching all trades of a portfolio and computing the net sum via a Python loop. On portfolios with large amounts of trades, this resulted in unbounded memory usage, high network overhead from transmitting all records, and slow execution. Database systems natively aggregate values via `sum()`, making an in-memory aggregation of rows entirely unnecessary unless each row requires logic unrepresentable in SQL.
**Action:** When computing sums or aggregations over large one-to-many relationship rows (e.g., all trades in a portfolio, all transactions for an account), offload the aggregation to the database using SQLAlchemy `func.sum()` instead of fetching `.all()` and looping in memory. Always profile the size of the result set before pulling `.all()` back into Python.
