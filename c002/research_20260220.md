# Research: Docker & Test Runner Stabilization (Ticket c002)

**Date**: 2026-02-20

## 1. Executive Summary
The Docker-based test runner (`test-runner` service) is currently failing because many components, especially within the test suite itself, hardcode service URLs to `localhost` instead of using the service names defined in the `docker-compose.yml` network. Additionally, there are inconsistencies in how the test database (`bsopt_test`) is handled compared to the production database (`bsopt`).

## 2. Technical Context
- **docker-compose.yml:291**: Defines `test-runner` with `DATABASE_URL=${DATABASE_URL_TEST}` (points to `postgres:5432/bsopt_test`).
- **tests/conftest.py:42**: Hardcodes `DATABASE_URL` to `localhost:5432/bsopt`, overriding any environment variables injected by Docker.
- **docker/Dockerfile.ci**: Uses Python 3.13 and installs all extras, which is correct for the project's requirements.
- **Makefile:137**: `test-all` target runs `docker compose --profile test run --rm test-runner pytest tests/`.

## 3. Findings & Analysis
- **Service Name Resolution**: Services inside the `bsopt-network` (bridge) should communicate using their service names (e.g., `postgres`, `redis`). Hardcoding `localhost` works only when running services directly on the host machine.
- **Test Database Mismatch**: The `postgres` service initializes the `bsopt` database, but the `test-runner` expects `bsopt_test`. If `bsopt_test` is not created during the initialization phase, the tests will fail to connect.
- **Widespread Hardcoding**: A `grep` search reveals dozens of instances where `localhost` is used as a fallback for `REDIS_URL` and `DATABASE_URL`, which is a "Jerry" pattern that prevents portable containerization.
- **Numba and CI**: `conftest.py` correctly disables Numba JIT for tests (`NUMBA_DISABLE_JIT=1`), which speeds up execution in CI environments.

## 4. Technical Constraints
- **Docker Compose Profiles**: The `test` profile is used to isolate the test runner from the main dev stack.
- **TimescaleDB**: The database image is `timescale/timescaledb:latest-pg16`, which requires specific extensions to be enabled (handled in `00-core-schema.sql`).

## 5. Architecture Documentation
- **CI Pipeline**: Optimized using a multi-stage Dockerfile (`Dockerfile.ci`) with `uv` for fast dependency management.
- **Test Infrastructure**: Relies on `pytest` and `docker-compose` to orchestrate a fresh environment for each run.
- **Environment Management**: Uses `.env` and `.env.test` for configuration, but enforcement is currently weak due to code-level overrides.
