# Research: Fix Postgres Schema and Missing Functions

**Date**: 2026-02-09

## 1. Executive Summary
The Postgres database is missing critical schema elements (columns `delta`, `gamma`, `implied_volatility` in `options_prices`) and the function `refresh_market_stats()`. This is because the `init-scripts/` directory is not mounted in the `docker-compose.dev.yml` file, preventing the `docker-entrypoint-initdb.d/` mechanism from executing the SQL scripts on first run.

## 2. Technical Context
- **Affected Component**: Postgres (Infrastructure)
- **Current Behavior**: 
    - `ERROR: function refresh_market_stats() does not exist`
    - `ERROR: column "delta" does not exist`
- **Related Files**:
    - `init-scripts/00-core-schema.sql`: Defines `options_prices` with the missing columns.
    - `init-scripts/07-market-stats-mv.sql`: Defines `refresh_market_stats()`.
    - `docker-compose.dev.yml`: Missing volume mount for `init-scripts/`.

## 3. Findings & Analysis
The Postgres container uses the `postgres:15-alpine` image. This image automatically executes any `.sql` or `.sh` files found in `/docker-entrypoint-initdb.d/` when the data directory is empty. However, the `postgres` service definition only mounts `postgres_data_dev:/var/lib/postgresql/data`. It lacks:
```yaml
    volumes:
      - ./init-scripts:/docker-entrypoint-initdb.d
```
Without this mount, the database is initialized with default tables (if any were created manually or via migrations) but skips the core schema and analytical functions.

## 4. Technical Constraints
- The `postgres_data_dev` volume already exists. Adding the mount won't re-run initialization if the data directory is not empty. We may need to force a re-initialization or apply the scripts manually.

## 5. Architecture Documentation
The project follows a "script-based initialization" pattern where infrastructure setup is defined in `init-scripts/`. This is a standard but brittle pattern if the orchestration layer (Docker Compose) isn't correctly configured.
