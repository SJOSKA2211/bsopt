# Research: Resolve 55 Ruff Linting Violations

**Date**: 2026-02-09

## 1. Executive Summary
The codebase contains 55 Ruff violations. The majority are `E402` (Module level import not at top of file), which often occurs when imports are interleaved with setup logic (e.g., `sys.path` modification or mocking). Other errors include `F841` (unused variables) and `E701` (multiple statements on one line).

## 2. Technical Context
- **Affected Component**: Entire project (Python sources and tests)
- **Current Behavior**: `ruff check .` fails with 55 errors.
- **Related Files**:
    - `bs_cli.py`: Multiple `E402` and `F841`.
    - `src/shared/shm_mesh.py`: `E701`.
    - `tests/conftest.py`: Unused imports (`F401`).
    - `tests/unit/test_arbiter_improved.py`: `E402` due to mocking patterns.

## 3. Findings & Analysis
- **E402 (Module level import not at top of file)**: 
    - In CLI/entry scripts (e.g., `bs_cli.py`), imports are often placed after setup code or within conditional blocks.
    - In tests, imports are often delayed until after `MagicMock` setup to ensure dependencies are mocked before they are loaded.
- **F841 (Local variable assigned but never used)**:
    - Example: `last_mesh_head` in `bs_cli.py`.
    - Example: `retrain` in `aiops_orchestrator.py`.
- **E701 (Multiple statements on one line)**:
    - Occurs in `src/shared/shm_mesh.py` with `if create: self.buf[:8] = struct.pack("q", 0)`.
- **F401 (Imported but unused)**:
    - Unused `mock_all` in `tests/conftest.py`.

## 4. Technical Constraints
- Moving imports to the top in tests might break mocking logic if the imports occur *before* the mocks are applied to `sys.modules`. We must use `# noqa: E402` or keep the structure if it's functional.
- Unused variables should be prefixed with `_` or removed.

## 5. Architecture Documentation
The project uses Ruff for linting and formatting. Current rules are defined in `pyproject.toml`.
