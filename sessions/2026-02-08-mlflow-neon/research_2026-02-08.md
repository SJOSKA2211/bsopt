# Research: Migrate MLflow to Neon DB

**Date**: 2026-02-08

## 1. Executive Summary
The current MLflow implementation defaults to local file storage (`./mlruns`) because the `tracking_uri` is not propagated from configuration to the `ExperimentTracker`. Additionally, the `Settings` class restricts Postgres-based tracking to the `prod` environment. To enable Neon DB tracking, we must update the configuration logic and ensure the tracking URI is correctly passed through the pipeline to the tracker.

## 2. Technical Context
- **Ticket**: `tickets/mlflow01/linear_ticket_mlflow01.md`
- **Configuration**: `src/config.py` defines `tracking_uri` but restricts it to `prod`.
- **Pipeline**: `src/ml/autonomous_pipeline.py` initializes `InstrumentedTrainer` (alias for `ModelTrainer`) without passing a `tracking_uri`.
- **Trainer**: `src/ml/trainer.py` accepts `tracking_uri` but defaults to `None`.
- **Tracker**: `src/ml/tracker.py` only sets the tracking URI if provided. It also fails to explicitly set the MLflow experiment name, causing runs to be logged under "Default".

## 3. Findings & Analysis

### 3.1. Broken Configuration Logic
In `src/config.py`:
```python
@property
def tracking_uri(self) -> str:
    """Point MLflow to Postgres in production."""
    if self.ENVIRONMENT == "prod":
        return self.DATABASE_URL.replace("postgresql+asyncpg", "postgresql")
    return "sqlite:///mlflow.db"
```
This forces `sqlite` in dev/staging, preventing integration testing with Neon.

### 3.2. Dropped Tracking URI
In `src/ml/autonomous_pipeline.py`, the `_train_and_optimize` method initializes the trainer:
```python
trainer = InstrumentedTrainer(study_name=self.study_name)
```
It fails to pass `tracking_uri` from `settings` or `config`.

### 3.3. Missing Experiment Context
In `src/ml/tracker.py`, the `__init__` method:
```python
def __init__(self, study_name: str, tracking_uri: str = None):
    self.study_name = study_name
    if tracking_uri:
        mlflow.set_tracking_uri(tracking_uri)
```
It stores `study_name` but never calls `mlflow.set_experiment(study_name)`.

## 4. Technical Constraints
- MLflow (via SQLAlchemy) requires a synchronous Postgres driver (`psycopg2` or `psycopg2-binary`).
- `DATABASE_URL` is typically `postgresql+asyncpg://` for the main async app. It must be converted to `postgresql://` for MLflow.
- `requirements.txt` confirms `psycopg2-binary` is installed.

## 5. Architecture Documentation
- **Current**: `AutonomousMLPipeline` -> `ModelTrainer` -> `ExperimentTracker` (Local FS)
- **Target**: `AutonomousMLPipeline` -> `ModelTrainer` -> `ExperimentTracker` (Neon DB)

## 6. Recommendations
1.  **Update Config**: Modify `settings.tracking_uri` to prefer Postgres if available, or allow manual override via `MLFLOW_TRACKING_URI`.
2.  **Pass URI**: Update `AutonomousMLPipeline` to retrieve `settings.tracking_uri` and pass it to `InstrumentedTrainer`.
3.  **Set Experiment**: Update `ExperimentTracker` to call `mlflow.set_experiment(self.study_name)`.
