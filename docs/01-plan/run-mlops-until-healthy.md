# Plan: Run MLOps Until Healthy

## Objective
Ensure the MLOps engine is fully operational and report its comprehensive health status.

## Background
The MLOps stack consists of several distributed services (MLflow, Ray, Training Workers) that depend on a core infrastructure (Postgres, Redis, MinIO). This plan automates the bootstrap, startup, and health verification of the entire engine.

## Scope & Impact
- **Impact**: Initializes the AI/ML training and inference environment.
- **Affected Services**: `mlflow`, `ray-head`, `ray-worker-1`, `rl-training-worker`, `mlops-worker`, and their infrastructure dependencies.

## Proposed Solution
1. **Initialize Environment**: Run the `bootstrap.sh` sequence to ensure PKI is setup and core infrastructure (Postgres, Redis, MinIO) is healthy.
2. **Start MLOps Profile**: Execute `scripts/start_mlops.sh` to launch the 'ml' profile services.
3. **Wait for Health**: The `start_mlops.sh` script includes built-in container-level health gates.
4. **App-Level Verification**: Run `bin/ml-health` to verify application-level connectivity and metrics (MLflow tracking, Prometheus metrics, Redis anomalies).
5. **Reporting**: Present the final health report generated by the engine.

## Implementation Steps

### Phase 1: Infrastructure Bootstrap
- Execute `./bootstrap.sh` until Phase B (Performance Backplane) is complete.
- Verify `postgres`, `pgbouncer`, `redis`, `rabbitmq`, and `minio` are healthy.

### Phase 2: MLOps Startup
- Execute `./scripts/start_mlops.sh`.
- Monitor logs for any startup failures in Ray or MLflow.

### Phase 3: Health Reporting
- Run `bin/ml-health --url http://localhost:8000/ml/health`.
- If the endpoint is not ready, wait and retry (up to 5 times).

## Verification
- `bin/ml-health` output shows status "HEALTHY".
- MLflow tracking UI is accessible at `http://localhost:5000`.
- Ray Dashboard is accessible at `http://localhost:8265`.

## Migration & Rollback
- **Rollback**: If startup fails consistently, run `docker-compose -f infrastructure/orchestration/docker-compose.yml --profile ml down`.
