Approach 1: Integrated Sentinel (Recommended)

Health Metrics Python

Integrate PgBouncer internal stats directly into system_sentinel.py. It will query the pgbouncer admin console for SHOW POOLS and SHOW STATS.

  • Pro: Single point of truth for system health.
  • Pro: Deep visibility into connection leakage.
  • Con: Requires admin credentials in the sentinel script.

Approach 2: Robust Orchestrator

Startup Automation Bash/Python

Revamp run_pgbouncer.sh to wait not just for the process, but for the upstream Postgres to satisfy specific health criteria (like Timescale extension readiness).

  • Pro: Prevents application startup until full stack is ready.
  • Pro: Auto-healing loops.
  • Con: Slightly more complex startup logic.

Approach 3: Dynamic Config Revamp

Optimization Configuration

Analyze pg_stat_activity and pgbouncer pools to automatically calculate and apply optimized pool sizes based on observed peak concurrency.

  • Pro: Tailored performance tuning.
  • Con: Risk of over-provisioning if not carefully bounded.
