# Research: Comprehensive Codebase Audit & Strategy

**Date**: 2026-02-06

## 1. Executive Summary
The **bsopt** codebase is a high-performance, multi-service financial platform integrating traditional quantitative finance (Black-Scholes, Heston) with modern Machine Learning (RL, Transformers) and Blockchain data. It uses a hybrid architecture with Python (ML/API), Rust/WASM (Compute), and Node.js (Auth), orchestrated via Docker.

## 2. Technical Context

### 2.1 Core Stack
- **Languages**: Python 3.13 (Backend/ML), TypeScript (Frontend), Rust (WASM).
- **Frontend**: React 19, Vite 7 (Rolldown), MUI v7, Three.js, ECharts (`src/frontend/package.json:1-40`).
- **Backend API**: FastAPI with `uvloop` and `Brotli` compression (`src/api/main.py:1-20`).
- **Auth**: Dedicated `auth-service` using `better-auth` (Node.js) (`docker-compose.prod.yml:32`).
- **ML/Compute**: PyTorch Lightning, MLflow, Ray, ONNX Runtime.
- **Infrastructure**: Docker Compose, Postgres 15, Redis 7, RabbitMQ, Kafka, Prometheus, Grafana (`docker-compose.prod.yml`).

### 2.2 Directory Structure
- `src/pricing`: Core financial logic (Black-Scholes, Heston, Monte Carlo).
- `src/ml`: Machine Learning components (RL Agents, Transformers, AIOps).
- `src/wasm`: Rust crate `bsopt-wasm` for high-performance pricing kernels (`src/wasm/Cargo.toml`).
- `src/frontend`: Modern React application.
- `init-scripts/`: Extensive DB initialization (`init-scripts/*.sql`).

## 3. Findings & Analysis

### 3.1 Architecture & Services
The application is decomposed into specialized microservices as defined in `docker-compose.prod.yml`:
- **`neural-pricing`**: Dedicated container for inference, optimized with OMP/MKL threads and quantization.
- **`worker-ml`**: Background processing with Celery and uvloop (`docker/Dockerfile.worker`).
- **`scraper`**: Data ingestion service.
- **`geth`**: Ethereum integration for blockchain data (`docker-compose.prod.yml:45`).

### 3.2 Performance Optimizations
- **WASM**: `src/wasm/Cargo.toml` dependencies (`wasm-bindgen`, `nalgebra`) indicate portable high-performance computing.
- **Ray**: Used for distributed training/serving (`ray-head` service in `docker-compose.prod.yml`).
- **FastAPI Optimization**: `src/api/main.py` explicitly imports and uses `uvloop` and `BrotliMiddleware`.
- **Database**: `init-scripts/04-timescale-hypertables.sql` and `init-scripts/08-continuous-aggregates.sql` confirm heavy usage of TimescaleDB features.

### 3.3 Dependencies
- **Python**: Locked to 3.13 (`pyproject.toml:16`).
- **Frontend**: Bleeding edge React 19 (`src/frontend/package.json:16`).
- **Rust**: `statrs`, `nalgebra`, `rand` for math/stats (`src/wasm/Cargo.toml`).

## 4. Technical Constraints
- **Complexity**: Hybrid stack (Python/JS/Rust) requires polyglot proficiency.
- **Deployment**: Requires orchestration of 10+ containers.
- **Hardware**: ML components (`neural-pricing`, `ray`) likely require significant RAM/CPU.

## 5. Potential Risk Areas (Audit Targets)
- **Integration Tests**: Verify interactions between `api`, `auth-service`, and `neural-pricing`.
- **WASM/Python Boundary**: Ensure data consistency between Rust kernels and Python wrappers.
- **Migration Scripts**: `init-scripts/` contains complex SQL logic that needs validation.
- **Security**: Auth is offloaded to a separate service; verify JWT/Session handling in `src/api`.
